## Problem Statement

空项目打开后，画布几乎只有平移和缩放。设计师没有「往桌上放东西」的一等入口，工具条缺位，看起来也不像完整创作台。

目标切片：**底部居中创作栏（气质完整、功能收敛）+ 文字/图片持久落桌 + 会话内撤销/重做。**  
不解决：Agent 生成落回、视频/音频、社区、阶段流水线、跨刷新撤销（入 TODOS.md #1）。

## What Makes This Cool

底栏一眼像「能干活的创作台」，不是残缺的空点阵；  
放下的字和图关掉再开还在，误操作能当场撤回来——自由桌才站得住。

## Constraints（修订后）

- 画布自由：不规定必须先放什么；工具条是能力入口，不是向导。
- 第一期按钮固定：手型 · 撤销 · 重做 · 文字 · 图片。
- 位置：画布底部居中浮条（胶囊/浮岛气质）。
- 落桌必须持久化：Artifact + desk layout，禁止仅内存草稿。
- **撤销/重做仅会话内（eng review D3 用户确认的降级，推翻原 premise 6）**：客户端内存快照栈，刷新后撤销栈清零。服务端操作历史进 TODOS.md #1，等 Agent 写桌切片再做。
- **画布图片入口仅收 JPEG/PNG（eng review D5）**；PDF 仅走聊天附件，PDF 画布预览进 TODOS.md #4。
- 不兼容旧流水线数据。
- 现有可复用：`ArtifactService.createPlaced`、`DeskStateService`、文件上传 API、前端 `Desk` 视口/拖动、`attachments.ts` 准入校验。

## 产品规格

### 底栏

- 位置：画布视口底部水平居中，浮于点阵之上，不挡右侧对话。
- 视觉：单行胶囊；图标 + 极简分隔；选中/禁用态（无可撤时撤销灰显）。
- 按钮顺序（左→右）：手型 · 撤销 · 重做 · 文字 · 图片。
- 不做：视频、音频、色板、复杂连线工具。

### 交互

| 动作 | 行为 |
|------|------|
| 默认 | 空白拖=平移；点物件=选中；拖物件=移动（现有） |
| 手型 | 取消选中；回到「空白拖=平移」 |
| 文字 | 视口中心创建便签（允许空文本），立即进入编辑；blur 有内容=appendVersion 提交，**blur 为空=删除该便签**（eng review T2） |
| 图片 | 文件选择器（accept `.jpg,.jpeg,.png`）→ 上传 → createPlaced 落桌 |
| 拖入画布 / 粘贴图片 | 同一落桌路径；复用 `attachments.ts` 准入校验，PDF/超 30MB 拒绝并提示 |
| 单击物件 | 选中（高亮）；点空白或手型取消 |
| 选中 + Delete/Backspace | 删除物件（硬删，进会话历史可撤） |
| Ctrl/Cmd+Z · Ctrl/Cmd+Shift+Z / Ctrl+Y | 撤销 / 重做 |
| **键盘守卫（硬性）** | 全局快捷键在 editable 目标（input/textarea/contenteditable）内一律不触发，不得抢浏览器/编辑器自身撤销 |

### 桌面物件类型（本切片）

新增显式类型：

- `sticky_note` — payload `{ text }`，**允许空文本**（渲染占位「输入文字…」）
- `canvas_image` — payload `{ file_id }`（eng review D4：file_id 为事实源，URL 由 `/api/files/:id` 派生；**创建时校验文件归属本项目且 mediaType∈jpeg/png**）

`understanding_note` / `design_directions` / `effect_image` 不在本切片范围内，且按 ADR 0012 已从 schema 删除；本切片创建路径只走 `sticky_note` / `canvas_image`。

### 会话内历史栈（修订后的撤销模型）

照抄 infinite-canvas 已验证模式（`project.tsx:165-170,366-398,949-985`），实现为 `useDeskHistory` hook：

- past/future 引用栈 + lastHistory 指针；条目持有重建所需的完整数据（**含 artifact id、payload、inputRefs、layout**）
- cap 50；新操作截断 redo 分支；180ms debounce 合并突发变更
- `applyingHistoryRef`（undo 应用不录历史）+ `historyPausedRef`（拖动中不录，drag end 单条提交）
- op 类型：place / move / remove / update_text；视口平移缩放、纯选中、聊天消息不进历史

#### 删除与撤销删除（eng review T1 定案）

- 删除 = 单事务：从 desk_state.objects 移除 + **硬删 artifact**（级联 versions）。新端点 `DELETE /api/projects/:id/desk/objects/:artifactId`。
- 撤销删除 = **同 UUID 重插**：客户端历史快照持完整 payload/inputRefs，调服务端 restore 路径（接受显式 id）原样重建，版本链从 v1 重启。**id 稳定，redo 与后续历史条目引用全部成立。**
- 已知限制：若文件在删除与撤销之间被 API 硬删，重建后图裂（当前无删文件 UI；GC 须避开可撤销窗口，见 TODOS.md #2）。

#### 幂等与串行化（eng review T3 + codex）

- 创建类操作带 `clientOpId`，服务端去重：超时重试不产生重复 artifact。
- 前端 desk 变更串行化 + stale refresh 序号守卫；move 失败回滚乐观态且不进历史。
- 上传不经 `useAttachmentDraft` 生命周期（避免聊天语义/清理误删）；复用准入校验 + `api.uploadFile`。

## Success Criteria（修订后）

1. 空桌底部可见完整气质创作栏（五钮）。
2. 点「文字」→ 便签出现且可编辑；blur 提交后刷新仍在。
3. 点「图片」或拖入/粘贴 JPEG/PNG → 图在桌上且刷新后仍在；PDF 被拒绝并提示。
4. 移动物件后刷新，位置保持。
5. **会话内**：撤销/重做覆盖 place/move/remove/update_text；**刷新后撤销栈清零是本期契约**。
6. 无可撤/无可重时按钮禁用；cap 触底正确。
7. 删除可撤销，撤销后物件同 id 重建，redo 成立。
8. 输入框内按 Delete/Ctrl+Z 不误伤画布。
9. 超时重试不产生重复物件（clientOpId 幂等）。
10. 不出现阶段向导文案或强制户型流程。
