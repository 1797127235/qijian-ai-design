# 家装方案约束包契约

**Status:** accepted  
**Date:** 2026-08-03

## Context

设计师确认一个设计方向后，需要一份可执行、可编辑、可追溯的设计依据。它服务于设计师和设计团队，不是客户提案、效果图提示词或施工图。方案约束包不能越权修改 CAD 几何，也不能把模型判断伪装成可信度。

## Decision

确认方向后自动生成一份 `design_system` 草稿。草稿必须由设计师编辑并确认，确认版本才可被后续设计阶段读取。第一版只实现家装适配器，通用结构为未来工装和景观扩展预留空间。

### 固定模块

家装第一版包含八个模块：

1. 结构与户型边界
2. 空间组织原则
3. 动线与关系
4. 功能与收纳
5. 材料与色彩边界
6. 家具与灯光原则
7. 预算与实施边界
8. 待确认事项

同时单独记录禁止项/不可接受项。每条约束包含内容、来源类别、来源对象、约束强度、待确认状态和设计师修改状态。

来源类别只有三种：

- `source_fact`：来自 CAD、Brief 或已确认项目理解；
- `design_decision`：来自已确认设计方向；
- `designer_added`：设计师直接补充。

约束强度只有三种：

- `hard`：必须遵守；
- `soft`：优先满足，但设计师可以调整；
- `unresolved`：尚未决定，不能作为生效约束。

模型输出和界面展示沿用设计师的主要工作语言。主要语言由 Brief 与设计师输入推断；CAD 图层名、品牌名和专业缩写保留原文。

### 几何与冲突

方案约束包只能引用并解释来源几何事实，不得静默修改墙体、门窗、楼梯、管线、开口、面积或主要动线。若设计方向与已确认事实冲突，必须创建冲突项并标记为 `unresolved`，交由设计师选择保留事实、调整方向或回到项目理解阶段修正事实。

### 编辑与局部重生成

设计师可以编辑、新增、删除和排序任意约束。所有编辑先产生草稿；确认后追加不可变版本，历史确认版本保留。重新生成只作用于当前模块，生成结果作为新草稿候选，不自动覆盖现有内容。项目理解或设计方向产生新确认版本时，方案约束包标记为“需要复核”，不自动重写。

### 追溯与界面

约束包采用单项目结构化编辑页，而不是三列长卡片。页面提供模块导航、主编辑区、来源回溯和版本确认。每条约束都能跳回其 Brief、项目理解、方向卡或原始资料依据。

## Consequences

- 后续方案生成读取的是设计师确认过的约束，而不是模型草稿；
- 设计师可以补充 AI 遗漏的专业判断；
- 约束冲突和来源变化被显式暴露，生成速度可能低于无确认门的流程；
- 工装和景观需要在通用信封之外定义各自的模块和校验规则；
- 方案约束包第一版不生成效果图、施工图或精确工程清单。

## Acceptance boundary

第一版必须支持自动生成草稿、八个家装模块、逐条来源和强度、编辑/新增/删除/排序、禁止项、单模块重生成、冲突标记、版本确认、历史差异和来源回溯；不修改 CAD 几何。
