# 结构化提案画布 MVP 实施拆解

## 目标

交付一条设计师可使用的纵向链路：已确认方案约束包进入空间地图，设计师校正空间后创建提案画布，选择关键空间并建立空间提案卡，手动挂载已有图片或参考资产。

本切片不接入新的效果图生成，也不导出客户提案包。

## 依赖输入

- 已确认 `design_directions`；
- 已确认 `design_system`；
- 关联的户型图或图纸 PDF 页面；
- 当前项目的原始参考资产。

## 纵向切片

### 1. 空间地图契约与持久化

新增 `space_map` 类型化 payload、版本创建接口和上游版本引用。一个 payload 对应一张图纸页面，保存归一化坐标的空间多边形和有类型关系。服务端拒绝无来源图纸、重复 `space_id`、退化多边形、跨页面关系和未确认空间地图作为提案画布输入。

### 2. 空间地图校正器

在桌面端以来源户型图为底图显示 AI 建议空间。设计师可选择、重命名、调整多边形顶点、修改用途、标记关键空间和维护空间关系。确认时追加不可变空间地图版本；不提供墙体、门窗或 CAD 编辑工具。

### 3. 提案画布与独立布局

从确认的空间地图、方向和约束包创建 `proposal_canvas`。画布中心以户型与空间区域为锚点，左侧展示项目依据，右侧展示当前空间检查器。`canvas_layout` 独立保存节点位置、尺寸、缩放、图层和叙事顺序，自动保存不改变设计语义。

### 4. 空间提案与人工资产挂载

系统提出 3 至 5 个关键空间候选，设计师确认、删除和排序。每个已选空间可建立可编辑 `space_proposal`。设计师可从项目已有图片、参考图或手动上传中挂载资产，并标记角色与采用状态。资产必须记录来源、空间、输入版本和采用状态。

### 5. 复核、分支与验收

上游确认版本变化后，服务端计算引用差异并将受影响空间提案/资产标记为 `needs_review`。支持从当前画布创建分支并选择其中一个分支；不支持合并。用真实家装项目验证空间地图校正、手动资产挂载、节点布局持久化和上游复核提示。

## 不在此切片中

- 真实效果图生成和局部重绘；
- 网页/PDF 客户提案包；
- 客户反馈界面；
- 团队实时协作；
- CAD/DWG/BIM 编辑或施工级尺寸；
- 移动端完整画布编辑；
- 自动合并画布分支。

## 验收场景

1. 设计师从一个已确认的方案约束包创建空间地图，校正客餐厅和主卧多边形并确认；
2. 设计师创建绑定该空间地图、方向和约束包版本的提案画布；
3. 设计师选择客餐厅、餐厨和主卧为关键空间，创建空间提案卡并挂载已有图片；
4. 设计师调整节点位置后刷新页面，布局仍存在，空间归属和约束引用不变；
5. 方案约束包确认新版本后，引用受影响约束的空间提案显示需要复核，历史资产不被删除；
6. 设计师从画布创建分支、在分支修改空间提案，并能明确选择一个分支作为后续提案包输入。
