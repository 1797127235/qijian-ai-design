# 意图：整案协同弧线（Agent 承接完整设计项目）

> 由 interview-me 流程确认（2026-08-12），用户已明确 yes。
> 与 [human-agent-desk-loop](human-agent-desk-loop.md) 的关系：那份管近程单点闭环（已通），这份管整案长弧线（下一步主线）。

## 确认的需求陈述

- **Outcome:** 上传一套设计资料（户型/参考图），Agent 作为同桌协作者陪你把整套方案做出来——理解图纸、提方向、按空间逐张出图、自己 look_at 验收、听纠正改图；中间不丢上下文、不重复犯错、桌面自己保持整齐。
- **User:** 先是产品作者自己 dogfood（当客户也当设计师），之后是独立家装设计师。
- **Why now:** 单点闭环已通，KV 缓存/上下文帧/项目记忆让「整案级长弧线」在成本与连续性上成立；缺的不是单点功能，是整条弧线不塌。
- **Success:** 一盘真实方案跑下来，用户的插手次数降到「只在真正需要做设计判断时说话」——纠语义、催进度、收拾桌面、重复解释已定事实全部消失；结束时桌上有一套愿意讲给客户听的图。
- **Constraint:** 协同，不是托管——设计裁决权始终在用户；Agent 自主的是执行、自检和桌面秩序。
- **Out of scope（近程）:** 不做无人值守全自治（不追求「睡一觉方案出好了」）；不做施工级几何对齐；不为这条弧线堆新工具墙（走既有 Agent 入口）。

## 访谈中的关键决策

| 问题 | 决策 | 理由 |
|---|---|---|
| 下一步是抛光还是新能力 | 新能力轴 | 照片堆/语义修正/提案包都被否：全是收拾残局，产品不长新能力 |
| 新能力落在哪条轴 | Agent 接更长的活（B） | 而非画面能力更深（A）或新产物类型（C）；KV 缓存基建正是为此打的门票 |
| 重点是执行可靠还是自主性 | 协同弧线本身 | 不是无人值守批量，也不是主动议程；是「上传一套方案 → 协同设计出来」的完整弧线不塌 |
| 弧线的敌人 | Day0 断点表 | 并发失控、wake 刷屏、落位乱、叙事断——第一仗是让长链不散，不是加新工具 |
| 协同感的核心 | 连续性 | 记得已定事实、记得被否方向、知道下一步该干什么 |
| 毕业演示 | A101 重跑 | 同一套资料，这次弧线完整走通 |

## 能力拆解（从 Day0 断点表反推，按依存排序）

1. **任务编排**：多空间出图从「一次性 ×N」变成有队列、有节奏的任务链（BullMQ 底座已在）。
2. **验收闭环**：出完必 look_at 对照；不合格换策略重试一次；连续失败停下来换打法（Day0 正例 #10 固化成机制）。
3. **wake 汇总**：同批任务结束合并成一条报告（断点 #2）。
4. **桌面秩序**：落位语义钉死（「重做」= replace /「再一版」= 旁落）；多空间出图有组织摆放。照片堆若回来，身份是「Agent 维护桌面秩序的手段」，不是收纳功能。
5. **连续性**：已定事实不重复问、被否方向不再提（项目记忆 + 上下文帧已铺路）。

## 背景事实

- 单点闭环已通：放图 → 点选 → AI 出图落回 → 再改（README「当前能力」）。
- 异步任务层：BullMQ + 独立 Worker，同项目图像并发上限内排队（ADR 0014）。
- Agent 写桌工具：`generate_from_desk` / `replace_on_desk` / `text_to_image_on_desk` / `remove_from_desk`，可 `look_at` / `look_at_desk` 验收。
- KV 缓存迁移进行中（M0–M3 核心 + M5 部分），长弧线的成本前提。
- Day0 dogfood：`docs/dogfood/a101-day0.md`；断点表与正例是本意图的直接证据。
- 远程终点不变：桌面内容长成后可给客户讲的全案汇报（见 human-agent-desk-loop）；本弧线走通前不动打包层。
