# 意图：人机同桌接力闭环（通往全案汇报）

> 由 interview-me 流程确认（2026-08-09），用户已明确 yes。

## 确认的需求陈述

- **Outcome:** 一张设计桌上，人和 Agent 接力完成设计。近程：跑通「看图 → 按话生成/改图 → 结果落位 → 人再改」。远程：同一工作方式自然长成可给客户讲的全案提案包（汇报）。
- **User:** 第一用户是产品作者自己当客户 dogfood；以后是家装设计师。入口必须内聚，不堆工具墙。
- **Why now:** 方向迷茫——想借鉴建筑学长类平台的能力深度，又反感入口杂、功能列表化；开发 Agent 正是为了把能力收成「少入口的同桌协作」。
- **Success:** 自己能串完一盘：桌上有愿意讲给别人听的图 + 说法；过程是「人说 → Agent 做 → 人改 → Agent 接着」，而不是点一堆独立按钮拼出来。结构可以糙，故事能串起来即可。
- **Constraint:** 产品作者不是设计师；提案包/汇报的目录结构后定，先证明闭环。近程以最短可演示路径为准。
- **Out of scope（近程）:** 建筑学长式工具超市与多业态入口墙；完整提案编辑器作为并行产品线；为清 TODOS 而开的工程债主线（跨刷新 undo、对比滑块等可后置）。

## 访谈中的关键决策

| 问题 | 决策 | 理由 |
|---|---|---|
| 对标什么 | 学建筑学长的出图能力深度，不学入口墙 | 用户明确要内聚，Agent 是实现手段 |
| 产品主形态 | 单桌 + 对话/Agent，人机同桌协调 | 人与 Agent 共用同一套物件与布局 |
| 近程切片 | 看图 → 按话生/改 → 落位 → 人再改 | 没有这条闭环，内聚叙事立不住 |
| 远程终点 | 全案提案包 ≈ 给客户看的汇报 | 桌面先长出内容，再整理/导出；非另开编辑器 |
| 第一用户 | 自己当客户 dogfood | 作者非设计师，先自证「能串一盘」再找真设计师验汇报结构 |
| 与 TODOS 关系 | 工程债不抢近程主线 | 成功标准是协作闭环与可讲故事，不是清单清空 |

## 背景事实

- 产品方向已定：图放桌上 → 点选 → AI 出图落回 → 再改；不强制 Brief / 空间地图 / 阶段关卡（见 README、CONTEXT.md）。
- Agent 写桌经 `generate_from_desk`（旁落）/ `replace_on_desk`（原卡）/ `text_to_image_on_desk`（文生）异步 Job 写 `effect_image`（ADR 0013）；可 `remove_from_desk`；可 `look_at_desk` / `look_at` 看桌。
- 已砍：空间地图、确认/采用审批、导出提案包壳、`proposal_package` 类型等；全案汇报是远程能力，需在闭环稳后再做打包层。
